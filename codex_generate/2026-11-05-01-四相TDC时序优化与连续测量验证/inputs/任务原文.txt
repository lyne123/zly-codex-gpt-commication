## 三、核心目标

本次任务分为三个主要目标。

**目标一：500 MHz 时序收敛**

要求：

- Baseline 和 Compensated 两个版本分别优化。
- 关键同步路径 Setup WNS ≥ 0。
- Hold WHS ≥ 0。
- 检查 TNS、THS、失败端点和约束覆盖率。
- 不允许通过降低主时钟频率来消除违例。
- 不允许随意添加 false path 或 multicycle path 掩盖真实违例。
- 不允许通过关闭 timing check 宣称时序通过。

**目标二：连续 PWM 测量**

重点检查：

- 20 MHz、50% duty。
- 20 MHz、5%/95% duty。
- 固定 25.3 ns 高电平脉宽。
- 10 MHz、50% duty。
- 上一轮 1056 单元的 ATC 暂定帧。

验证是否存在：

- 丢上升沿；
- 丢下降沿；
- 重复 valid；
- 极性冲突；
- 上下沿错误配对；
- FIFO overflow；
- 脉宽异常跳变。

**目标三：建立严格对照实验**

分别运行：

1. 原始 RTL 行为仿真。
2. 原始实现后 SDF 仿真。
3. 时序优化后 RTL 行为仿真。
4. 时序优化后实现后 SDF 仿真。

## 六、第三阶段：针对性优化 RTL

根据关键路径报告选择最小修改方案。

优先考虑：

### 6.1 组合逻辑分级

- 比较与优先级编码分离。

不能机械增加流水级。

对新的 post-route 实现重新提取补偿参数，并用独立数据集验证。

## 七、第四阶段：连续测量问题定位

本阶段最重要的是区分：

**时序违例引起的错误**与**RTL 算法自身的事件处理限制**。

### 7.1 RTL 与 SDF 对照

对上一轮出现的 3 个丢失上升沿、2 个丢失下降沿和 2 次错误配对，记录对应事件编号。

在 RTL 行为仿真中复现完全相同的输入激励。

重点观察：

- `sync_edge_valid`
- `sync_edge_polarity`
- `sel_index`
- `polarity_conflict`
- `chosen_code`
- `edge_valid`
- `pulse_width_valid`
- FIFO 写使能及错误标志

记录每个异常事件在流水线各级的传递过程。

### 7.2 因果分析

判断每次异常属于哪种情况：

A. RTL 行为仿真已出现同样错误。

说明该错误不依赖实际布局布线延迟，优先怀疑 RTL 逻辑、事件处理能力或 testbench。

B. RTL 行为仿真正常，SDF 仿真出现错误。

进一步检查对应事件是否有真实同步路径时序违例、X 传播、采样窗口问题或模型差异。

C. 优化后 SDF 仿真错误消失。

记录消失的具体事件及对应修复路径，说明时序改善与错误消失之间的证据关系。

D. 时序优化后错误仍存在。

说明不能仅依靠时序优化解决，需要进一步检查候选选择和事件配对逻辑。

特别关注同一采样帧内出现不同极性候选时，原 RTL 是否会直接丢弃整帧。

本次只分析这一问题，暂时不要重构成多事件队列。

### 7.3 异步 TDL 时序告警

TDL 利用异步 PWM 与采样时钟之间的时间差工作，部分采样触发器的 setup/hold 告警可能与正常测量机制有关。

必须区分：

- TDL 异步采样寄存器相关告警。
- 时钟同步数字逻辑真实违例。
- 不合理 CDC 导致的违例。
- 测试模型产生的告警。

不允许直接把所有 `$setuphold` 告警认定为同步时序错误，也不允许全局关闭告警。

## 十二、验收标准

### Timing PASS

- 500 MHz 同步关键路径 WNS ≥ 0。
- WHS ≥ 0。
- TNS、THS 不存在未解决的负裕量。
- 重要路径约束覆盖完整。
- 无通过不合理时序例外隐藏的真实违例。

### Functional PASS

- 固定脉宽测试通过。
- 20 MHz 连续测量无丢沿。
- 无错误配对。
- 无重复 valid。
- FIFO 不溢出。
- 时间戳及脉宽不存在未解释的异常跳变。

### Compensation PASS

- 补偿前后使用相同测试数据。
- 新补偿参数来自对应物理实现。
- 补偿逻辑没有引入新的功能错误。
- RMSE、Bias、STD 有可信对照结果。

整体只有全部验收通过才能标记 PASS。

如果 Timing 已通过但 Functional 未通过，必须分别报告，不能混为一谈。

不允许为了得到 PASS 而降低测试难度或改变验收条件。
